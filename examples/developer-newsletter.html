Why Stripe Still Writes Their Own HTTP Client

When Stripe published their internal engineering principles in 2023, one line stood out: "We prefer writing small, focused libraries over depending on large, general-purpose ones." Their HTTP client is the clearest expression of that principle.

The client they use today was written in 2017. It handles exactly four things: connection pooling, retry logic with jitter, request signing, and structured error deserialization. It does not handle cookies, redirects, or multipart forms. It does not need to. 

# Simplified representation of Stripe's retry approach
def request_with_retry(method, url, body, max_retries=3):
    for attempt in range(max_retries):
        resp = client.request(method, url, body)
        if resp.retryable and attempt < max_retries - 1:
            sleep(backoff(attempt))  # jitter applied
            continue
        return resp
